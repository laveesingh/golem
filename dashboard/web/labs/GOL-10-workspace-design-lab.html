Architectural Blueprint

Zero-Terminal Lead Agent Interaction Model

Solving the persistent manual lead dilemma with On-Demand Turn Execution & Checkpointing.

⚡
1. On-Demand Turn Execution (Ephemeral Slices)
Instead of running a forever-open terminal process, the dashboard spins up a focused Lead turn on-demand when the user requests actions (e.g. "Brainstorm Spec", "Decompose Tasks", "Verify Spec"). Context is bounded to the exact spec, recent tracker comments, and repository map.
🔄
2. Dashboard-Managed Background Daemon
The dashboard server (`worker-manager.js`) handles worker spawning, status polling, and health monitoring in detached tmux/process groups. Users can peek console scrollback, steer mid-turn, or stop workers with 1 click without ever running `tmux attach`.
🧹
3. Automatic Compaction & Checkpoint Restarts
When a spec closes or milestones are hit, the session state is compacted into durable memory (`memory_add`). Future turns start from a fresh slate, preventing context window fatigue, hallucination, and exorbitant API costs.

Architectural Analysis & Recommendation

1. Why The Spec Cockpit (Direction 1) Wins

Real agentic work is 95% spec drafting, comment refinement, and worker dispatching. Consolidating the Spec Tree, Document Reader, and Live Worker Operations into a single 3-pane screen eliminates 100% of the manual page navigation between Tracker, Specs, Logs, and Terminal.

2. Elimination of Dead Top-Level Pages

Prunes `/tracker`, `/specs`, `/logs`, `ideas-drawer.jsx`, and `drawer-ceo.jsx`. Retains `/project/:id` as the primary cockpit, `/agents` as system diagnostics, and `/settings` for harnesses & model profiles.

3. Zero-Terminal First Flight

New users are greeted with automated environment readiness checks, 1-click project onboarding, guided spec drafting with AI templates, and automated background worker dispatch without ever typing in a bash shell.
