# Golem 6.0 — planned breaking wave (not released)

Foundations imports the already-released 5.26.1 version/lock/plugin stamp from exact upstream 39a80536. This is not a 6.0 version bump, publication, reinstall, or main merge. Slice owners add release details under their own heading; an empty section is not an acceptance claim.

## S1 · Stores and entity contracts (W3)

### Existing W3 pilot input policy

GET /api/health and POST /api/tickets gain canonical TypeBox/JSON Schema/OpenAPI contracts. Existing health/create fields and semantic/malformed-JSON error bodies are preserved; nullable fields are explicit, unknown request fields are not stripped, and defaults remain handler-owned.

Intentional body type hardening: numeric title/project_id previously accepted201 now return400/invalid_input. Declared body JSON types are no longer coerced. BEFORE snapshots remain the evidence of that deliberate change, not a fake unchanged conversion.

### Versioned local stores

`config.json`, `dashboard.json`, and `share-tunnel.json` gain `schema_version: 1` and migrate in place: files without the tag keep every known field and unknown extension JSON and validate as v1 on read; only an explicit save stamps the tag. A stored version higher than 1 is refused instead of being silently defaulted, and a failed owner write keeps the previous bytes. Journal (`hook.jsonl`) and spool (`<session_id>.jsonl`) files gain a first-line version header (`{"schema_version":1,"kind":"journal"|"spool"}`) on creation; readers accept header-less legacy files unchanged and refuse a higher header version. Spool headers are metadata and are never forwarded as bus events.

## S2 · CLI JSON envelopes (W8)

Every `golem ... --json` form returns one flat envelope: success
`{ schema_version, ok: true, ...fields }`, failure
`{ schema_version, ok: false, error: { code, message, details? } }`.
Raw arrays become `{ ..., items }`; management lists stay
`schema_version: 2`, all other families start at 1. GOL-404 fields are
unchanged and gain `ok`; existing recovery and partial-outcome fields stay
flat, and the old string `error` becomes the structured error. Parse and
validation errors return the envelope wherever `--json` appears on the command
line. Exit codes and human-readable output are unchanged. One result schema per
verb family lives in `lib/contracts/cli.ts` and is emitted to
`contracts/dist/Cli*.schema.json`. Every reader is listed in
`docs/testing/cli-json-consumers.md` and parses through the envelope.

## S3 · Emitted and bundled renders (W7)

`golem sync --target cc` and `--target pi` now emit JavaScript for every
TypeScript helper on the copy lists, so no render executes `.ts` through Node.
The Claude render bundles `mcp/channel` into one ESM entry with esbuild: the
render no longer carries `mcp/channel/node_modules`, a re-sync prunes the old
tree, and `substrate/mcp.json` drops its `NODE_PATH`. Renders also carry
`contracts/dist` and a `.golem-render.json` marker that asset lookups resolve
from. After upgrading, re-run `golem sync --target cc` and `--target pi`, then
update the installed plugin.

## S4 · Clock and recorded scenarios (W5)

No user-facing behaviour changes, with one fix: `pushControlEnvelope` in the
dashboard threw `legacy is not defined` for every Claude-session control message
other than `session_notify` (gate verdicts, interrupts, halts) since
`759f7b68`; 6.0 restores it. Internally, `lib/clock.ts` is injected into the
dispatch drainer and the delivery timers, and four scenarios recorded from real
runs (Pi typed dispatch, Claude channel dispatch, herdr worker lifecycle,
dashboard restart with a stranded envelope) replay in the integration tests.

## S5 · Design-system atoms and molecules (W4)

No user-facing change: the components are not mounted in the live dashboard
yet. `dashboard/web/src/ui/` gains five atoms (Button, IconButton, Input, Pill,
Badge) and four molecules (Card with CardHeader, ListRow, Menu, EmptyState),
token-only and shell-neutral, each with a Ladle story, a component test, an axe
check and pinned Linux screenshot baselines.

## S6 · Scrub wave 1 (W6)

### Removed REST routes

- `POST /api/tickets/:id/move` and the tracker `moveTicket()` method. Use `PATCH /api/tickets/:id` with `{state}` for state changes. The dashboard board already uses PATCH; no persisted neighbour-rank ordering is introduced. Existing rank data is not deleted.
- `GET /api/channels`. Read channels from `/api/snapshot` or its WebSocket updates. Delivery's internal channel discovery remains.
- `GET /api/channel/health` and its route-only `channelHealth()` helper. `/api/communication-health` remains the active diagnostic surface; it is not an exact replacement for the removed proxy response.
- `GET /api/projects/:id`. Select the project from `/api/projects` or `/api/snapshot`.
- `GET /api/projects/:id/plan` and its route-only `projectPlan()` helper. Project summaries already carry `plan`. PLAN.md remains supported.

These routes are absent from generated `contracts/dist/openapi.json`. They have no in-tree consumer after removing the unused wrappers; external REST clients must stop using them for 6.0.

### Removed adapters and dependencies

- Unused `SubstrateAPI.workspaces`, `channels`, `channelHealth`, `addLink`, and `removeLink` web adapters. No component called them. The link POST/DELETE REST routes and persisted links remain because API smoke scripts consume them.
- Direct dependencies `@dnd-kit/sortable`, `@dnd-kit/utilities`, and `ws`. The first two had no source imports. The admitted HTML block-service integration test now uses Node's built-in `WebSocket` instead of `ws`; its post-commit update assertion remains. Clean `npm ci` and dashboard build are required for this removal. Transitive `@dnd-kit/utilities` (core) and `ws` (Fastify/jsdom) remain where needed.
- `jsonc-parser` and `@babel/parser` stay: both now have consumers.

### Removed scripts and instruction-size reporting

- Historical `dashboard/scripts/jsx-check.mjs`, the only W0 script classified historical. Vite's dashboard build remains the syntax/build check. Other unwired/manual scripts stay; W0's table remains a historical census.
- The instruction word-count warning associated with `golem sync --check` is retired. The base already stopped calling the lint module from sync; S6 deletes orphan `lib/compiler/lint.js` and removes its instruction-reading test call. Sync drift/tamper checks and render parity tests remain. No instruction-content check replaces it.

### Moved research

- Root `agent-cache-cost-simulator.html` moves unchanged to `docs/research/agent-cache-cost-simulator.html`.

### Earlier foundations removals

- `lib/process-group.js` no longer exports the named `processGroupExactMatches` function. The existing exported `processGroup.processGroupExactMatches` facade method and its body remain unchanged.
- The unused named `processHasDescendants` function is removed. Its last authority-path consumers and tests were removed by upstream's scoped-management release; no capture/identity/signal/terminate behavior is changed or restored.

These named-export surface removals are explicit future6.0 changes, not a zero-surface cleanup or a released-contract compatibility pass.
