# Golem6.0 — planned breaking wave (not released)

Foundations imports the already-released5.26.1 version/lock/plugin stamp from exact upstream39a80536. This is not an authored6.0 version bump or publication/reinstall/main merge.

## W3 pilot input policy

GET /api/health and POST /api/tickets gain canonical TypeBox/JSON Schema/OpenAPI contracts. Existing health/create fields and semantic/malformed-JSON error bodies are preserved; nullable fields are explicit, unknown request fields are not stripped, and defaults remain handler-owned.

Intentional body type hardening: numeric title/project_id previously accepted201 now return400/invalid_input. Declared body JSON types are no longer coerced. BEFORE snapshots remain the evidence of that deliberate change, not a fake unchanged conversion.

## Touched-slice removals

- `lib/process-group.js` no longer exports the named `processGroupExactMatches` function. The existing exported `processGroup.processGroupExactMatches` facade method and its body remain unchanged.
- The unused named `processHasDescendants` function is removed. Its last authority-path consumers and tests were removed by upstream's scoped-management release; no capture/identity/signal/terminate behavior is changed or restored.

These named-export surface removals are explicit future6.0 changes, not a zero-surface cleanup or a released-contract compatibility pass.

## Explicit remaining release gates

W3 versioned unversioned stores/JSONL headers, emitted installed package/assets/link acceptance; W7 standalone emitted/bundled renders; W8 flat CLI envelopes; W6 removals; W4 components/E2E and W5 genuine scenario/clock acceptance remain uncompleted. File version/artefact details will be added when their consumers are actually repaired. Instruction-size lint removal is recorded by the foundations work but no instruction-content gate is reintroduced.

This note is a future6.0 plan, not a compatibility pass against released5.26 schemas (that release has no canonical schema artefact).
