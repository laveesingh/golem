# 5.26.1 — Scoped controls without authority vetoes

Human-directed replacement of the 5.26.0 stop/control policy:

- Stop closes the selected native pane. No captured-incarnation, application-lease, adoption, or caller-authority veto. The current contents of that selected pane are stopped, including restarted apps.
- Read, attach, rename and move likewise use selected native placement rather than process ownership gates. External mapped agents can be stopped without adoption.
- An explicit native session scopes name lookup across its teams; an inferred caller team does not silently narrow it. Team selectors and exact IDs identify one target.
- Ambiguity returns matching identities, runtime IDs, teams, sessions and projects with `TARGET_AMBIGUOUS` / `needs_selection` (exit2). No mutation happens until one target is selected.
- Native execution/connection failures remain failures, with a readable action and no false stopped record. Team close retains unrelated panes, not the explicitly targeted member pane.
- Removed the superseded application-ownership gate and its stop-refusal tests; replaced them with real native scoped-stop/close, stale-metadata, ambiguity and runtime-error tests.

This does not claim every native integration or authenticated model journey was rerun. Existing authentication and provider settings are unchanged.
