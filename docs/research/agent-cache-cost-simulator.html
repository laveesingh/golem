6 · What is actually going on (the in-depth bit)

KV-cache / prompt caching in one paragraph

A transformer re-computes attention over every input token on every request — unless the provider kept the already-computed key/value tensors (KV-cache) for an exact prompt prefix. In an agent loop the harness re-sends the whole transcript each turn, so turns 2…N mostly re-send bytes the provider has already processed. Providers expose that reuse as prompt caching: the first time a prefix is seen you pay a cache-write surcharge to store it; later identical prefixes are billed at the cheap cache-read rate; output tokens always cost full output price (including hidden reasoning tokens).

Anatomy of one warm turn vs one cold turn

Warm: input = old transcript (cache READ, e.g. $0.50/MTok on Opus 5) + new tail (last output + tool results, cache WRITE so next turn hits). Only the small tail pays full-ish price — that is the "tiny fraction at input cost" effect you described.

Cold: the TTL lapsed (long tool run, lunch break, compaction, prefix edit, model unload). The whole context — say 30–40k tokens by mid-run — is re-processed and re-written at write price (2× base on Anthropic 1-h, 1.25× on 5-min/OpenAI). Mid-run colds dominate the bill, which is why this simulator forces two of them (turns 5 and 9 by default).

Subscription vs API — when these numbers apply

Claude Code on a Pro/Max subscription: flat monthly fee with a usage allowance — no per-token bill inside the allowance; caching just stretches the allowance further. Claude Code on API credits: every token bills exactly as simulated here. Pi is always BYO-key / OAuth-metered: the simulation is the bill (plus any ChatGPT/Codex plan allowance on the OpenAI side). Ollama-local = $0 + your hardware.

Assumptions & limits of this simulator
  • Transcript resend model: input(n) = input(n-1) + output(n-1) + fresh(n). Each row's output/tail is editable; appended turns inherit the section-2 output default and the dock tail value. Compaction, summarisation, and sub-agent contexts are not modelled.
  • Warm-turn tail billed at write price by default (harness re-caches); toggle in §2 for base-price tail.
  • OpenAI cold turns billed at the 1.25× write rate; granularity (128-token steps) ignored — immaterial at these sizes.
  • OpenAI prompts >272k input tokens bill 2× input/cache and 1.5× output — applied automatically, badge in the table.
  • Reasoning / thinking tokens (if any) bill as output; tool-call fees (search, code-execution) excluded.
  • Single-run view: no batch/flex discounts, no enterprise tiers, taxes excluded.
